# План 9 — Зеркальный Двойник: выбор кита по классу игрока

**Спека:** `Docs/Design/2026-09-10-boss-concepts-roster.md`, босс №15 (этажи 6–8).
**Зависит от:** плана 1 (пул и фреймворк китов).
**Даёт играбельным:** одного босса, но **три разных боя** — по одному на класс. После него в пуле 18.

Двойник копирует класс игрока. Это единственный способ показать игроку его собственный класс со стороны, и самая высокая отдача на единицу работы во всей роспиcи: один ассет — три боя.

---

## 1. Решение: варианты кита живут на монстре, а выбор — в чистом селекторе

`MonsterData.bossKit` — одно поле, и оно остаётся: это набор по умолчанию. Рядом появляется список вариантов:

```
[System.Serializable] public class BossClassVariantKit { public CharacterClass playerClass; public BossKitData kit; }
public List<BossClassVariantKit> classVariantKits;
```

Выбор выносится в `MirrorKitSelector.Select(MonsterData, CharacterClass)` — чистая функция, по образцу `BossPoolSelector`: без вариантов и при отсутствии совпадения возвращает `bossKit`. Так поведение проверяется тестом без сцены и без фабрики, а фабрика остаётся тупым исполнителем.

**Почему не «кит с ветками внутри».** Ветка по классу внутри `BossKitData` заставила бы `BossEncounterState` знать о классах игрока, а он сейчас не знает о них ничего и не должен: его задача — фазы и кулдауны.

## 2. Решение: фабрика получает готовый кит, а не класс игрока

`CreateMonsterCombatant` читает `monster.bossKit` напрямую. Вместо того чтобы протаскивать `CharacterClass` через всю фабрику, добавляется необязательный параметр `BossKitData kitOverride = null`, а выбор делает новая точка входа:

```
public static CombatantRuntime CreateBossCombatant(MonsterData boss, int floorNumber, CharacterClass playerClass, CombatantRuntime player = null)
```

`CreateBossCompanions` перестаёт перечитывать `bossData.bossKit` и берёт кит с уже собранного рантайма (`bossRuntime.BossEncounter.Kit`) — иначе вариант класса выбран, а спутники пришли бы из кита по умолчанию.

## 3. Решение: «120 % статов игрока» — это ПОЛ, а не замена

Спека называет ~120 % статов игрока митигацией против «двойник слишком лёгкий для того, кто знает свой класс наизусть». Буквальная замена статов сделала бы босса с 54 HP против Саши — это не бой, а недоразумение.

Поэтому `BossKitData.mirrorPlayerStatsPercent` работает как **нижняя граница**: собственные статы двойника от `MonsterData` берутся как есть, но если они оказались ниже указанного процента от статов игрока — подтягиваются до него. Двойник никогда не слабее игрока и никогда не теряет свою боссовую массу.

Подтягиваются HP и урон оружия. Броня и уклонение НЕ подтягиваются: они заданы веткой класса осмысленно (Дженифер — броня, Вайолет — уклонение), и общий пол их бы смазал.

## 4. Три ветки

Общее у всех: *Отражение* — HeavyAttack ×1.8, кд 12 с, телеграф 2 с. Фаза 2 на 50 % HP: «зеркало треснуло», копия класса спадает, остаётся обычный, но более быстрый набор.

| Против | Чем отвечает | Что проверяет |
|---|---|---|
| Дженифер (Warrior) | высокая броня | оборона против обороны, затяжной бой |
| Вайолет (Rogue) | уклонение и яд | нужен объём урона, а не только пик |
| Саша (Barbarian) | копит Enrage и разгоняется | гонка на выносливость против её же механики |

**Thorns-отражения не будет.** Спека предлагает его для ветки Дженифер, но отдельного эффекта «отражать урон» в игре нет, а заводить его ради одной ветки дороже, чем он даёт: в автобое игрок на отражение всё равно не реагирует. Ветка Дженифер строится на броне и `StatDebuff`, то есть на уже существующем.

`CharacterClass.Mage` в игре не используется (Мага нет), поэтому ветки для него нет — сработает набор по умолчанию.

## 5. Порядок работ

1. Данные: `BossClassVariantKit`, `classVariantKits`, `mirrorPlayerStatsPercent`.
2. Тесты до кода: селектор возвращает вариант/дефолт; фабрика ставит выбранный кит; спутники берут кит с рантайма; пол статов подтягивает слабого и не трогает сильного.
3. `MirrorKitSelector`, точка входа в фабрике, правка `CreateBossCompanions`.
4. Вызов из `CombatRoomFlow` с классом персонажа.
5. Ассеты: три кита, монстр, спрайты фаз, запись в пул.
6. Честность: тест, что у монстра с вариантами есть ветка для каждого ИГРАБЕЛЬНОГО класса (Warrior/Rogue/Barbarian).
7. Проверка: EditMode + смоук.

## 6. Чего этот план НЕ делает

- Не вводит Thorns (см. выше).
- Не копирует активный навык игрока: двойник копирует роль класса, а не конкретную кнопку. Копия навыка потребовала бы ИИ его применения, а это не механика босса, а второй игрок.
- Не трогает выбор цели и спавн: двойник — одиночный бой.
