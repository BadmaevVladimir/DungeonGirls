# План 8 — спавн миньонов: Пожирающий Амальгам и Паучиха-Прародительница

**Спека:** `Docs/Design/2026-09-10-boss-concepts-roster.md`, боссы №7 (Амальгам, этажи 3–6) и №13 (Паучиха, этажи 5–7).
**Зависит от:** плана 3 (мультиэнкаунтер) — он уже дал группу, якоря и `TickBossGroups`.
**Даёт играбельным:** двух боссов, после чего в пуле 17.

Оба боса — «приоритет цели», но с разной формой давления: у Амальгама куски отделяются по порогам HP (ступенчато), у Паучихи кладка идёт по таймеру (ритмично). Это единственная причина, по которой их имеет смысл делать одним планом: механика спавна общая, а ощущение от боя разное.

---

## 0. Что уже есть и переиспользуется без изменений

- `BossCompanionSpawn` + `CombatantFactory.CreateBossCompanions` — спутники **на старте боя**. Миньоны появляются по ходу, поэтому это не тот механизм; но `MarkGroupMember` переиспользуется.
- `TickBossGroups` — снижение урона, пока жив кто-то из группы. Это ровно «Кокон» Паучихи, новый эффект не нужен.
- `BossAbilityTriggerKind.OnCombatStart` — «один раз при входе в текущую фазу». Это ровно пороговый спавн Амальгама (66 %, 33 %), новый triggerKind не нужен.
- `ApplyDot` (план 5) — Poison для «Кислотного плевка» и «Ядовитого укуса».
- `groupDamageReductionPercent` (план 3) — «Кокон».

---

## 1. Решение: миньон — это поле способности, а не спутник кита

`BossCompanionSpawn` описывает состав сцены на старте. Миньон — результат срабатывания способности. Смешивать их в одно поле значит сделать `companions` списком с двумя несовместимыми смыслами.

Новые поля в `BossAbilityConfig` (дописываются в конец, ключи YAML отсутствующие у старых китов сохраняют инициализаторы — проверено тестом `EveryPhaseEntryMultiplier_...`):

```
public MonsterData spawnMonster;      // кого ставим
public int   spawnCount = 1;          // сколько за одно срабатывание
public int   spawnAliveCap;           // потолок одновременно живых, 0 = без потолка
public float healPercentOfMaxHp;      // для ConsumeMinion
```

## 2. Решение: два новых effectKind, оба дописываются в конец enum

Порядок значений `BossAbilityEffectKind` сериализован в YAML по индексу — **только дописывание в конец**.

| effectKind | Кому | Что делает |
|---|---|---|
| `SpawnMinions` | Амальгам, Паучиха | Ставит `spawnCount` копий `spawnMonster`, не превышая `spawnAliveCap` живых миньонов этого боя. Если потолок уже выбран — способность срабатывает вхолостую (кулдаун всё равно уходит). |
| `ConsumeMinion` | Амальгам | Если жив хоть один миньон — убирает одного и лечит босса на `healPercentOfMaxHp` от его макс. HP. Если миньонов нет — вхолостую. |

**Потолок обязателен, а не желателен.** Спека, раздел «класс-чек» Паучихи: каждый лишний атакующий — лишний бросок против уклонения Вайолет. Потолок 3 — условие проходимости, поэтому он проверяется тестом честности по всем китам, а не только у Паучихи.

## 3. Решение: «Кокон» — это группа плана 3, а не новый эффект

Спавненный миньон помечается `InBossGroup = true` через тот же `MarkGroupMember`. Тогда `TickBossGroups` сам даёт боссу −25 %, пока жив хоть один паучонок, и сам снимает их, когда последний умер.

Одна поправка: `TickBossGroups` выдаёт снижение **каждому** члену группы (так задумано для симметричных Близнецов). Паучатам живучесть не положена, поэтому у спавненного миньона `PendingGroupDamageReductionPercent` принудительно обнуляется сразу после пометки. Босс остаётся единственным выгодоприобретателем.

Солобонус (`soloDamageBonusPercent`) у обоих китов = 0, поэтому смерть последнего миньона не даёт боссу усиления — только снимает «Кокон».

## 4. Решение: миньоны умирают вместе с боссом

Иначе добитый босс оставляет на сцене трёх паучат, и бой продолжается без боса — победа перестаёт совпадать со смертью босса.

`CombatantRuntime.IsBossMinion` + проверка в `TickBossGroups`: если миньон жив, а ни одного живого врага с `BossEncounter != null` на сцене нет — миньон умирает. Проверка живёт рядом с остальными правилами группы, потому что это ровно то же наблюдение «кто ещё жив».

## 5. Решение: карточки врагов достраиваются, а не пересобираются

`BuildEnemyStageEntries` строится **один раз на бой** — это фикс выбора цели кликом (`ClickEvent` рождается только если PointerDown и PointerUp пришли в один элемент; пересборка каждый кадр ломала выбор). Спавн меняет состав сцены по ходу боя, то есть впервые нарушает это допущение.

Нельзя: звать `BuildEnemyStageEntries` заново — это `Clear()`, то есть возврат сломанного выбора цели.
Надо: `SyncEnemyStageEntries()` — достраивает карточки только тем врагам, у кого записи ещё нет, и удаляет записи исчезнувших (съеденный миньон). Существующие карточки и их обработчики не трогаются.

Размер спрайта: у миньона нет кита, поэтому `BossStageLayout` считает его обычным врагом (260px). Рядом с 518-пиксельным боссом трое таких забивают сцену — добавляется `MinionSize = 190f` и ветка по `IsBossMinion`, сразу после ветки якоря.

## 6. Порядок работ

1. **Данные.** `IsBossMinion` в `CombatantRuntime`; поля спавна в `BossAbilityConfig`; два значения в конец `BossAbilityEffectKind`.
2. **Тесты (до кода).** Потолок живых; спавн вхолостую при выбранном потолке; `ConsumeMinion` лечит ровно на процент и только при живом миньоне; смерть босса убирает миньонов; «Кокон» включается и выключается; миньон не получает снижение урона.
3. **Механика.** Два `case` в `ExecuteBossAbility`; правило сиротства в `TickBossGroups`.
4. **Сцена.** `BossStageLayout.MinionSize`; `SyncEnemyStageEntries` вместо разовой сборки.
5. **Ассеты.** `Monster_AmalgamSlug`, `Monster_Spiderling` (+ спрайты), `Monster_Amalgam`, `Monster_Broodmother`, `BossKit_Amalgam`, `BossKit_Broodmother`, записи в `BossPool_Main`.
6. **Честность.** Тест: любая способность со `spawnMonster` обязана иметь `spawnAliveCap` в 1..3.
7. **Проверка.** EditMode + смоук.

## 7. Чего этот план НЕ делает

- Не трогает `DamageReduction` как отдельный effectKind (план 4) — «Кокон» выражается группой.
- Не даёт миньонам собственных китов: `CreateBossCompanions` намеренно не рекурсивен, спавн наследует то же правило.
- Не занимается ИИ выбора цели у игрока в авто-режиме: спека обоих боссов требует ручного переключения, это и есть решение.
