# 0. Vision / Scope прототипа

Для прототипа необходимо реализовать:

Core Loop — (пункты 1-6). 3 этажа подземелья, 5 разных комнат, 3 типа противника, 1 босс, 1 персонаж (10 уровней прокачки), 10 пассивных навыков, 3 активных навыка, 3 сцены на привале, 10 типов снаряжения для каждого слота, 1 персонаж-ментор (заглушка).

Мета прогрессия — 3 здания в деревне по 5 уровней. 3 уникальных бонуса за 5 уровень каждого здания.

Гача система — 10 плейсхолдер предметов для потенциального эндгейма и 2 персонажа.

> ПРИМЕЧАНИЕ: цифры этого раздела устарели и заменены фактическим контентом в других разделах: пассивных навыков фактически 11 (10 общих/классовых из 3.9 + 1 уникальный персонажа из 3.1), активный навык только 1 (уникальный Дженифер, «3 быстрые атаки») — общего/классового пула активных навыков нет в прототипе; типов снаряжения на слот не 10, а 3 тира x 4 архетипа для оружия, 3 тира для брони/шлема/сапог, 7 вариантов для колец/аксессуаров (только Редкий), см. 3.9-3.10 для точных цифр.

# 1. Core Loop

Выбор подземелья > Выбор персонажа > Выбор наставника > Запуск подземелья > Забег > Победа\Поражение в подземелье > Расчет и выдача наград > Добавление персонажа в колоду ветеранов.

## Подробное описание этапов:

1. **Выбор подземелья.** На главном экране игрок выбирает одно из доступных ему подземелий. В прототипе будет всего одно подземелье, но в финальной игре будут доступны разные подземелья в зависимости от сюжета и активных ивентов. Каждое подземелье имеет свои модификаторы. Стартовое подземелье дает +5 рационов на забег.
2. **Выбор персонажа.** После выбора подземелья игрок видит список персонажей, которые подходят под условия подземелья. Это может быть ограничение на классы, уровни возвышения (количество копий одного героя из гачи) или на статус ветерана (можно ли проходить это подземелье только новым персонажем или одним из ветеранов). В прототипе доступен только один персонаж и ограничение стартового подземелья это только новые герои (не ветераны).
3. **Выбор наставника.** Игрок выбирает одного наставника из списка ветеранов, который передаст новому персонажа часть своих навыков (случайным образом) и свой основной пассивный навык (но его нельзя прокачать, в отличие от остальных навыков). В прототипе будет один наставник, который будет являться заглушкой.
    
    [DRAFT] [DRAFT] Наставник-заглушка — ветеран класса **Маг**. Его основной пассивный навык — **«Магнум Опус»**: +10% к магическому урону персонажа (уровень 1, не прокачивается при передаче подопечному, согласно правилу выше). Уровень остальных навыков (не основной пассивный), передаваемых от наставника подопечному: передаётся частично — половина от уровня навыка у ветерана, округление вниз. Открытый вопрос: сколько именно навыков передаётся, точное число не определено.
    
4. **Запуск подземелья.** Генерация уровней. Оповещение игрока о потенциальных модификаторах этого подземелья. После запуска подземелья игрок может выйти из забега, только добровольно приняв поражение.
5. **Забег.** Отдельный loop со своей state machine. Подробнее описано ниже.
6. **Победа/поражение в подземелье.** Завершение забега, выход из подземелья на экран наград и итогов.
7. **Расчет и выдача наград.** Расчет наград игрока в зависимости от его результатов в подземелье. Успешное завершение даёт дополнительные награды.
8. **Добавление персонажа в колоду ветеранов.** Расчет ранга персонажа, его уровня силы и снаряжения. Запись персонажа в колоду ветеранов, чтобы использовать его в других режимах или в качестве наставника.

## Loop Забега:

Вход в стейт забега > Генерация подземелья > Определение типа комнаты > прохождение комнаты > подведение итогов комнаты > персонаж мертв — выход из core loop забега и переход на этап расчета наград | персонаж жив — выдача наград и опыта > если есть припасы — предложение привала > если соблюдены условия — запуск сцены на привале > восстановление части здоровья > продолжение забега.

### Подробное описание этапов забега:

1. **Вход в стейт забега.** Игра получает информацию о характеристиках персонажа, модификаторах подземелья и всем остальном.
2. **Генерация подземелья.** Игра генерирует этаж подземелья. Определяется количество комнат, количество особых комнат и босс этажа.
3. **Определение типа комнаты.** Перед тем, как игрок заходит в комнату, игра определяет тип комнаты. Это боевая комната с противниками, комната с боссом, особая комната, ивентовая комната или комната торговца.

# 2. Генерация подземелья

## 2.1 Общая структура

Для прототипа — **3 этажа** (фиксировано).

Количество комнат на этаже задаётся составом мешка с комнатами (см. 8.4) — для первого этажа это 12 комнат; на более глубоких этажах состав мешка вырастает (точные числа пока не определены).

Путь внутри этажа — **линейный** для прототипа (без ветвлений).

Тип каждой комнаты (бой/торговец/особая, см. раздел 5) выбирается **без повторения из мешка** (bag randomization) — подробности и состав мешка см. 8.4.

## 2.2 Боссы

Для прототипа используется **1 общий босс**, повторяющийся на всех 3 этажах с усилением (масштабируется по этажам, см. 2.6). В будущем возможен переход на отдельных боссов на каждом этаже, если позволит скоуп разработки.

[DRAFT] **Статы босса** (база — этаж 1, дальше масштабируется как обычные монстры, см. 2.6): HP 150, физ. защита 12, урон физический случайный 15-20, скорость атаки 1.2/сек. Баланс-логика: броня 12 не пробивается стартовым оружием (6 урона) без апгрейда снаряжения — это намеренно, согласно цели «не проходимо без прокачки» (см. ниже).

[БАЛАНС-НАХОДКА, важное для понимания экономики]: Стартовое оружие Дженифер (6 урона, см. 3.1) ФИЗИЧЕСКИ НЕ ПРОБИВАЕТ броню Скелета (10, см. 2.4) и босса (12) — даже с критом (150% = 9) или макс. «Я — стена» (+1.5 флэт) урон всё равно не пробивает 10-12 брони. Это СОЗНАТЕЛЬНО создаёт гейт: без апгрейда оружия (через Кузницу или лут) игрок не может убивать бронированных врагов (Скелет, босс), только безбронных (Слизь, Колдун).

## 2.3 Противники (структура)

У монстров та же базовая структура, что и у персонажа: **HP + навыки**, но вместо отдельного снаряжения у них есть **встроенный аналог статов снаряжения** (урон, скорость атаки, защита) напрямую в характеристиках монстра — отдельное снаряжение им не прописывается.

## 2.4 Противники (типы для прототипа)

**Слизь.** Много HP, низкая скорость атаки, физический урон. Простая «губка для урона», учит игрока базовому бою. HP 50, урон случайный 8-12, скорость атаки 0.7/сек.

**Скелет.** Имеет броню (физическую защиту), среднее HP, нормальная скорость атаки, физический урон. «Стандартный» моб, показывает, что у противников тоже бывает броня. HP 40, физ. защита 10, урон случайный 10-15, скорость атаки 1.0/сек.

**Колдун.** Имеет магическую защиту, много магического урона, мало HP. Пассивный навык на снижение скорости атаки у игрока. Более продвинутый моб, показывает, что у противников тоже бывают навыки. HP 30, маг. защита 20, урон магический случайный 13-20, скорость атаки 1.0/сек. Пассивка «Проклятие замедления»: если урон Колдуна проходит по здоровью персонажа, скорость атаки персонажа снижается на 30% на 3 секунды (не стакается, повторное попадание обновляет длительность).

## 2.5 Модификаторы этажа

Отдельны от модификаторов подземелья (которые действуют на весь забег, см. раздел 1). Модификаторы этажа действуют только на конкретном этаже и меняются от этажа к этажу.

[DRAFT] Черновые примеры модификаторов этажа для прототипа (связаны с бонусами Храма, см. 8.1):

- **Этаж 1:** без фиксированного дебаффа — стартовый этаж, только модификаторы подземелья (см. раздел 1).
- **Этаж 2:** «Ядовитый воздух» — персонаж теряет 2% от максимума здоровья каждые 10 секунд в бою (тик-урон). Снижается/убирается прокачкой Храма ур. 2.
- **Этаж 3:** «Гнёт тьмы» — весь входящий урон персонажа увеличен на 15%. Снижается/убирается прокачкой Храма ур. 4.

Это напрямую объясняет, почему бонусы Храма (8.1) именно «снижают/убирают дебафф 2го/3го этажа» — эти дебаффы гарантированно присутствуют на соответствующих этажах без прокачки здания.

Позиция комнаты босса внутри линейного пути этажа: **подтверждено** — комната босса всегда последняя в пути этажа.

## 2.6 Масштабирование монстров по этажам

[DRAFT] Статы в разделе 2.4 — базовые (этаж 1). На каждом следующем этаже: HP x1.25, урон x1.15 (множители накапливаются, этаж 3 = x1.5625 HP / x1.3225 урон от базы). Скорость атаки и защита не масштабируются.

# 3. Персонаж: характеристики, навыки, снаряжение

## 3.1 Базовые параметры персонажа

У каждого персонажа есть:

**Стартовый персонаж прототипа: Дженифер** (Класс Воин).

- **Здоровье.** Количество здоровья на первом уровне и количество дополнительного здоровья, получаемого за каждый левел-ап. [DRAFT] Для стартового персонажа: 20 HP на 1 уровне, +20 HP за каждый следующий уровень.
- **Уникальный пассивный навык.** Известен персонажу с 1 уровня (с самого начала забега). Может прокачиваться несколько раз, предварительно — до 5 уровней.
- **Уникальный активный навык.** Известен персонажу с 1 уровня (с самого начала забега). Предварительно может прокачиваться до 3 раз.
    
    Для стартового персонажа (Класс Воин) навык — **«3 быстрые атаки»**: персонаж наносит 3 быстрых удара, каждый с множителем от базового урона оружия (см. 3.2), зависящим от уровня навыка:
    
    - Уровень 1: каждая из 3 атак — 110% урона оружия
    - Уровень 2: каждая из 3 атак — 130% урона оружия
    - Уровень 3: каждая из 3 атак — 150% урона оружия
    
    (т.е. суммарный урон за активацию — 330%/390%/450% от базовой атаки, в зависимости от уровня навыка)
    
    [DRAFT] Кулдаун навыка: 4 секунды.
    
- **Класс.** Определяет, какие предметы персонаж может надевать. Для прототипа — 1 класс, **«Воин»**. Всё создаваемое для прототипа снаряжение считается подходящим для класса Воин 100% времени (в забеге не должно выпадать неподходящее снаряжение, т.к. его нельзя ни продать, ни перенести в другой забег). На будущее в структуре данных предмета нужно предусмотреть поле **список допустимых классов** (для будущего расширения на другие классы), а также поле **слот снаряжения** (см. 3.4) — даже если для прототипа все предметы подходят классу Воин, поле должно быть заложено архитектурно.
    
    Пассивка — **«Полевой ремонт»** [DRAFT]: на привале восстанавливает % от максимума физ. защиты (складывается с бонусом Кузницы, см. 8.1; при макс. ур. обоих = полное восстановление брони на привале, приемлемо для прототипа):
    
    - Ур. 1: 10%
    - Ур. 2: 20%
    - Ур. 3: 30%
    - Ур. 4: 40%
    - Ур. 5: 50%
- **Стартовое снаряжение.**
    - Железный меч (оружие, слот 1): урон 6, скорость атаки 1.5/сек
    - Деревянный щит (оружие, слот 2): +3 к максимуму физ. защиты
    - Железный нагрудник (броня, торс): 11 физ. защиты
    - Остальные 5 слотов пусты в начале забега

## 3.2 Урон

За урон почти полностью отвечает снаряжение, а не сам персонаж (кроме случаев, когда навыки персонажа могут влиять на урон).

У оружия есть:

- Урон
- Тип урона
- Скорость атаки (количество атак оружием в секунду)

У оружия более высокого тира могут также быть:

- Бонусы к характеристикам
- Пассивные навыки (почти как у персонажа)

## 3.3 Защита

Реализовано два типа защиты: физическая и магическая.

**Магическая защита:**

Работает как дополнительный пул здоровья, который поглощает магический урон, пока не закончится. Восстанавливается до максимума после каждого боя. Значение магической защиты может суммироваться с нескольких предметов одновременно (не привязано к одному конкретному слоту).

**Физическая защита (броня):**

Работает иначе, чем магическая:

- Если физический урон меньше значения физической защиты — урон не проходит по персонажу вообще.
- Если физический урон больше значения физической защиты — защита снижает урон на своё значение, остаток урона проходит по здоровью персонажа, после чего значение физической защиты снижается на 1.
- Таким образом физическая защита может закончиться (выработаться) в течение забега.

Для упрощения расчётов параметр физической защиты как таковой есть только у предмета в слоте "Броня" (торс). Остальные предметы могут только влиять на её максимум (например, шлем может увеличивать максимум физической защиты брони на 10, но сам по себе значения физической защиты не имеет).

Если физическая защита снижена до 0, предмет не исчезает — её можно восстановить (почистить) различными навыками. Известные на сейчас источники восстановления:

- Уникальный пассивный навык персонажа в прототипе (предварительно) позволяет восстанавливать часть физической защиты на привале.
- Планируется особый предмет — оружие "Кузнечный молот" (высокая редкость), пассивный навык которого восстанавливает часть физической защиты после боя.

## 3.4 Слоты снаряжения

Всего 8 слотов:

- Шлем
- Броня (торс) — единственный слот, несущий параметр физической защиты (см. 3.3)
- Сапоги
- Оружие/руки — 2 слота (может быть 2 оружия, либо оружие + щит, либо другая комбинация предметов в руках)
- Кольца — 2 слота
- Аксессуар — 1 слот

**Без инвентаря:** для прототипа отдельного экрана инвентаря не будет. При получении нового предмета (из сундука или от торговца) он сравнивается с текущим надетым предметом того же слота/подтипа, и игрок выбирает: надеть новый (старый при этом просто исчезает, не сохраняется) или выбросить новый. Нет склада/хранилища предметов в прототипе.

## 3.5 Прокачка навыков (левел-ап)

**Гача и стартовый уровень:**

Копии персонажа, полученные в гаче, увеличивают стартовый уровень персонажа в начале забега и повышают уровни его уникальных навыков (потолок доступного уровня прокачки).

**Прокачка внутри забега:**

В основном навыки прокачиваются за счёт повышения уровня персонажа во время забега. Система вдохновлена левел-апом в Vampire Survivors и играх, вдохновлённых им.

При получении уровня (после боя в комнате) игроку открывается окно выбора с 3 вариантами навыков (число вариантов может быть увеличено прокачкой определённых зданий в городе).

**Источники вариантов в окне:**

- Общие навыки — из отдельного списка, общего для всех героев
- Навыки класса — из отдельного списка, специфичного для класса персонажа
- Дополнительные уникальные навыки героя — доступны только персонажам повышенной редкости, становятся доступны в процессе прокачки (это отдельные навыки сверх базового уникального пассивного/активного навыка из п. 3.1)

Часть вариантов в окне — новые навыки, часть — апгрейд уровня уже известных персонажу навыков. Шанс появления варианта-апгрейда уже известного навыка: 50% (черновое значение, требует баланс-тестов).

**Слоты пассивных навыков:** у персонажа одновременно может быть известно максимум **5 разных пассивных навыков** (из общего/классового пула, см. 3.9; уникальный пассивный навык персонажа из 3.1 в этот лимит не входит, он отдельный). [ОТКРЫТЫЙ ВОПРОС: что происходит, если все 5 слотов заняты и в окне левел-апа появляется новый (ещё не известный) навык — заменяет один из существующих, вообще не показывается в окне выбора, или что-то ещё — не определено.]

**Прокачка уникального пассивного навыка (2-5 уровень):**

Базовый уникальный пассивный навык персонаж знает с 1 уровня. Его дальнейшие уровни (2-5) игрок получает через то же окно выбора при левел-апе — как один из вариантов апгрейда уже известного навыка, наравне с общими и классовыми навыками.

**Прокачка уникального активного навыка (2-3 уровень):**

Базовый уникальный активный навык персонаж знает с 1 уровня. Возможность прокачать его следующий уровень появляется каждые 5 уровней персонажа (5, 10, 15...). Апгрейд активного навыка появляется в том же окне выбора, что и пассивные навыки, занимая один из 3 (или более, см. выше) слотов — то есть конкурирует с остальными вариантами, а не добавляется как отдельный/дополнительный вариант.

Если апгрейд активного навыка не выбран сразу при первом появлении (например, на 5 уровне), он остаётся в списке потенциальных вариантов для выбора в последующих окнах, пока не будет выбран. Следующий уровень активного навыка (после того как текущий апгрейд выбран) станет доступен на следующей контрольной отметке уровня (10, 15...) с теми же условиями.

## 3.6 Опыт и кривая уровней

[DRAFT] Опыт для следующего уровня = уровень x 25 (1->2: 25, 2->3: 50, 3->4: 75, 4->5: 100, 5->6: 125, 6->7: 150, 7->8: 175, 8->9: 200, 9->10: 225).

Источники опыта [DRAFT]: обычная боевая комната - 10, успешное событие/ловушка - 5, босс - 50.

## 3.9 Общий и классовый пул навыков (левел-ап)

Все навыки ниже прокачиваются до 5 уровня (если не указано иное), согласно 3.5.

### Общие навыки (доступны всем героям)

**Заморозка** — при нанесении урона по здоровью противника накладывает 1 стак «заморозки». 1 стак снижает скорость атаки цели на 5% на 3 секунды. Повторное наложение увеличивает штраф и обновляет длительность. Максимум стаков по уровням: 1ур=2, 2ур=4, 3ур=6, 4ур=8, 5ур=10. При достижении 10 стаков противник «замораживается» на 5 секунд (не может атаковать/применять способности). Физический урон по замороженному противнику «разбивает» его: наносится доп. магический урон, равный полученному физическому, после чего противник получает иммунитет к заморозке на 5 секунд.

**Удача** — повышает шанс успеха ловушек/квестов (см. 8.3): каждый уровень навыка = +1 эффективный уровень персонажа в формуле шанса успеха. На 5 уровне дополнительно даёт 10% шанс получить доп. награду из сундука в конце боя (см. 8.2).

**Уклонение** — шанс полностью проигнорировать атаку противника: 1ур=5%, 2ур=10%, 3ур=15%, 4ур=20%, 5ур=25%.

**Прочный** — увеличивает физ. защиту персонажа: 1ур=+5%, 2ур=+10%, 3ур=+15%, 4ур=+20%, 5ур=+25%.

**Критические атаки** — шанс нанести крит (150% урона оружия): 1ур=10%, 2ур=20%, 3ур=30%, 4ур=40%, 5ур=50%.

### Классовые навыки — Воин

**«Я — стена»** — часть бонуса брони от щита добавляется к урону оружия (флэт-бонус): 1ур=10%, 2ур=20%, 3ур=30%, 4ур=40%, 5ур=50% от значения бонуса щита к броне.

**Амбидекстрия** — снижает штраф за двойное оружие. [НОВОЕ ПРАВИЛО БОЯ]: если персонаж экипирует оружие в оба слота рук (см. 3.4), он атакует обоими оружиями одновременно, но каждое с сокращённой силой. Базовый штраф без навыка = 75% силы атаки каждого оружия. Уровни навыка увеличивают этот %: 1ур=90%, 2ур=100%, 3ур=110%, 4ур=120%, 5ур=130%. Работает только при двух оружиях в руках (не влияет на связку оружие+щит).

**Шипы** — если атака противника не пробивает броню (блокируется полностью, см. 3.3), часть заблокированного урона отражается обратно: 1ур=20%, 2ур=40%, 3ур=60%, 4ур=80%, 5ур=100%. На 5 уровне также отражает 50% урона, даже если атака пробила броню.

**Несгибаемый** — пока на персонаже есть дебафф, его урон увеличен: 1ур=+5%, 2ур=+10%, 3ур=+15%, 4ур=+20%, 5ур=+25%.

**Кровотечение** — при нанесении физического урона по здоровью противника накладывает кровотечение на 3 секунды (не стакается, повторное попадание обновляет длительность): 1ур=5 урона/сек, 2ур=10, 3ур=15, 4ур=20. На 5 уровне урон остаётся 20/сек, но длительность становится бесконечной.

## 3.10 Каталог снаряжения (примеры по тирам)

### Уровень предмета (отдельная шкала от тира/редкости)

Каждый уровень предмета даёт **+10% к базовым статам** (мультипликативно, накапливается поверх множителя тира): `ФинальныйСтат = БазавыйСтат × МножительТира × (1 + 0.1 × (УровеньПредмета − 1))`. Стартовое снаряжение Дженифер (3.1) — уровень 1. Максимальный уровень предмета пока не ограничен — открытый вопрос.

### Множители тира (редкости, см. 8.2)

Обычный ×1.0 (без бонусных статов/пассивок). Редкий ×1.5 (+ бонусный стат). Эпический ×2.2 (+ ТОТ ЖЕ бонусный стат, что и у Редкого тира этой же линии предмета — не новый, а тот же самый, просто унаследован от Редкого; так решено пока чтобы не придумывать второй бонус + пассивный навык, может быть общим навыком из 3.9 на 1 уровне).

### Архетипы оружия (подтипы, трейд-оф)

На будущее в структуре данных предмета закладывается поле **подтип** (аналогично списку допустимых классов, см. 3.1) — для ограничения снаряжения по классам в будущем. Для прототипа подтипы заданы только для оружия; остальные слоты — один общий тип на слот пока.

**Меч** — сбалансирован. База (Обычный, ур. 1): урон 6, скорость 1.5/сек.

**Топор** — высокий урон, низкая скорость. База: урон 10, скорость 1.0/сек.

**Копьё** — низкий урон, высокая скорость. База: урон 4, скорость 2.0/сек.

**Молот** — самый высокий урон, самая низкая скорость. База: урон 14, скорость 0.7/сек.

Все 4 архетипа примерно равны по DPS на базе (~8-10), различаются частота/бурстность атак.

### Примеры предметов по тирам (уровень 1 в каждом случае)

**Мечи:** Железный меч (Обычный, урон 6) → **Стальной гладиус** (Редкий, урон 9, бонусный стат: +1.5% шанс крита за каждый уровень предмета) → **Кровавый меч** (Эпический, урон 13.2, бонусный стат: +1.5% шанс крита за уровень предмета — как у Стального гладиуса, пассивка «Вампиризм»: восстанавливает здоровье в размере 2% от урона крита за каждый уровень меча).

**Копья:** **Железное копьё** (Обычный, урон 4) → **Стальное копьё** (Редкий, урон 6, бонусный стат: +5% скорость атаки за каждый уровень предмета) → **Стремительное копьё** (Эпический, урон 8.8, бонусный стат: +5% скорость атаки за уровень (как у Стального копья), пассивка **«Насквозь»**: 1% урона за каждый уровень предмета дополнительно проходит по всем остальным противникам в комнате, помимо выбранной цели).

**Молоты:** **Железный молот** (Обычный, урон 14) → **Стальной молот** (Редкий, урон 21, бонусный стат: +10 HP за каждый уровень предмета) → **Молот кузнеца** (Эпический, урон 30.8, бонусный стат: +10 HP за уровень (как у Стального молота), пассивка «Ремонт»: +1% за каждый уровень предмета к восстановлению брони на привале, складывается с «Полевым ремонтом» персонажа и бонусом Кузницы, см. 3.1, 8.1).

**Броня (торс):** Железный нагрудник (Обычный, физ.защита 11) → **Стальной нагрудник** (Редкий, 17, бонусный стат: +10 HP за каждый уровень предмета) → **Эфирный доспех** (Эпический, 24, бонусный стат: +10 HP за уровень (как у Стального нагрудника), пассивка «Неуловимость»: 1% за каждый уровень предмета шанс полностью не получить урон от атаки, складывается с общим навыком «Уклонение», см. 3.9).

**Шлем (+макс. физ.защита):** Простой шлем (Обычный, +5) → **Стальной шлем** (Редкий, +8, бонусный стат: +1% урона за каждый уровень предмета) → **Корона Мидаса** (Эпический, +12, бонусный стат: +1% урона за уровень (как у Стального шлема), пассивка «Золотое касание»: +1% за каждый уровень предмета к получаемой валюте забега из сундука, см. 8.2).

# 4. Бой (автобой)

## 4.1 Общий характер боя

Бой идёт в реальном времени, а не пошагово. Каждый участник боя (персонаж и противники) атакует со своей скоростью атаки независимо от остальных — скорость атаки оружия персонажа задаётся в характеристиках оружия (см. 3.2, атак в секунду).

В обычной боевой комнате может быть несколько противников одновременно. Количество привязано к уровню персонажа [DRAFT, баланс-решение против риска нескольких Колдунов в одной комнате одновременно]: уровень 1-3 — всегда 1 монстр в комнате; уровень 4-6 — случайно 1-2; уровень 7-10 — случайно 1-3. Они атакуют персонажа по своим собственным кулдаунам (независимо друг от друга и от персонажа).

[БАЛАНС-НАХОДКА]: без этого ограничения 2-3 Колдуна одновременно могли бы убивать стартовую Дженифер (20 HP, 0 маг. щита) за менее 1 секунды в ОБЯЗАТЕЛЬНОм бою (в отличие от ловушки, бой нельзя пропустить). Ограничение кол-ва монстров по уровню решает это естественным образом.

## 4.2 Таргетинг

Игрок может нажатием на конкретного противника выбрать его целью для персонажа — тогда персонаж фокусирует все свои атаки на выбранной цели.

Если игрок не выбрал цель вручную, персонаж по умолчанию атакует ближайшего/первого в списке противников.

## 4.3 Активация уникального активного навыка

Активный навык может срабатывать в одном из двух режимов, между которыми есть переключатель:

- **Автоматический режим.** Навык активируется сам по готовности кулдауна, без участия игрока. Ручное нажатие в этом режиме недоступно/не требуется.
- **Ручной режим.** Игрок сам нажимает на кнопку навыка, когда хочет его применить (по аналогии с AFK-батлерами на мобильных устройствах, например AFK Arena). Кнопка активна только когда кулдаун навыка истёк.

Цель активного навыка при активации: зависит от типа конкретного навыка (сингл-таргет, AoE или сам на себя) — единого правила для всех навыков нет, каждый навык описывает это отдельно в своём описании.

## 4.4 Урон и защита в бою

Применяются формулы и правила из раздела 3.2-3.3:

- Физический урон — блокируется полностью, если меньше значения физической защиты; иначе защита снижает урон на своё значение и теряет 1 единицу, остаток урона проходит по здоровью.
- Магический урон — поглощается магической защитой (суммарной со всех предметов), пока та не закончится; magic-щит восстанавливается после боя.

## 4.5 Условия окончания боя

Лимита времени на бой нет. Бой идёт до тех пор, пока одна из сторон не погибнет (все противники в комнате либо персонаж мертвы, HP ≤ 0).

## 4.6 Противники в бою

Противники атакуют персонажа обычной атакой по своему кулдауну, но также могут иметь собственные навыки (активные/пассивные), которые они применяют по своей логике (не обязательно у каждого противника; конкретная логика описывается отдельно для каждого типа противника, см. раздел 2).

# 5. События/комнаты

## 5.1 Общая структура

Согласно Core Loop (раздел 1), комната может быть одного из типов:

- **Боевая комната** — бой с обычными противниками. Механика — см. раздел 4.
- **Комната с боссом** — уникальный бой, механика — см. раздел 4.
- **Комната торговца** — см. 5.2.
- **Ловушка** — отдельный тип верхнего уровня (не подтип особой комнаты) — см. 5.5.
- **Особая комната** — общее название для остальных «нетипичных» комнат (ВН-триггер/квест/скриптованная встреча) — ловушка в эту категорию НЕ входит, она отдельный тип (см. выше). См. 5.3.
- **Ивентовая комната** — отложена на будущее. Идея: если в игре в данный момент идёт какой-то ивент (например, Рождество), в подземелье могут быть особые комнаты, завязанные на этом ивенте (особые монстры и т.д.). Не нужно для прототипа, оставлено здесь как напоминание.

## 5.2 Комната торговца

Торговец в подземелье работает за **валюту забега** — отдельную от мета-валюты, обнуляется в конце забега.

Предлагает **3-4 случайных предмета** из пула этажа. Продать своё снаряжение торговцу **нельзя** (чтобы не делать это слишком выгодным при большом количестве лута). Посещение комнаты торговца **не тратит рацион**.

## 5.3 Особая комната

Общая категория для нетипичных комнат. Для прототипа планируются реализовать следующие варианты особой комнаты:

- **Триггер ВН-сценки** — запускает сцену визуальной новеллы.
- **Скриптованная встреча** — запускает бой (через механику раздела 4, но с предварительным триггером/контекстом).
- **Текстовый квест с выборами** — см. 5.4.

## 5.4 Текстовый квест с выборами

Игроку показывается описание ситуации и несколько вариантов ответа (выборов) на выбор.

В **большинстве случаев** выбор ведёт к гарантированному исходу (без проверки/шанса).

В **некоторых случаях** у выбора есть шанс провала, основанный на уровне ответа (аналогично механике ловушки, см. 5.5): уровень ответа сравнивается с уровнем персонажа, и от этой разницы зависит шанс успеха. Шанс успеха может дополнительно зависеть от класса персонажа или наличия у него необходимых навыков (бонус к успеху).

**Важно:** квесты персонаж-специфичны — общего нейтрального пула квестов нет. Это сделано намеренно: квесты — одно из немногих мест в игре, где можно раскрыть личность конкретного героя. Одна и та же сцена/ситуация может переиспользоваться для разных героев, но подаётся с точки зрения их личности — текст, выборы и реакция героя отличаются.

### Примеры квестов для Дженифер

**Загадка сфинкса.** При входе в комнату Дженифер натыкается на сфинкса, который загадывает классическую загадку про существо с 4, 2 и 3 ногами. Игроку даются несколько вариантов ответа.

- Правильный ответ (гарантированно, без проверки уровня — это вопрос знания, не шанса): бонус к деньгам в следующем бою.
- Неправильный ответ: в следующем бою игрок не получает валюту из сундука (см. 8.2).

**Круг фей.** В комнате обнаруживается круг, похожий на круг фей. Можно попытаться лечь там на отдых (это будет считаться привалом, см. раздел 6), или просто пройти мимо (ничего не происходит). Уровень квеста — 5.

- Успех: Дженифер восстановит больше здоровья на этом привале.
- Провал: она восстановит только половину обычного объёма привала, потому что весь привал её мучали кошмары.

**Меч в камне.** В комнате стоит меч, втокнутый в камень. Можно попытаться его вытащить. Уровень квеста — 10.

- Успех: игрок гарантированно получает меч высокой редкости.
- Провал: Дженифер теряет уверенность в себе и в следующем бою наносит на 10% меньше урона.

## 5.5 Ловушка (отдельный тип комнаты верхнего уровня, см. 5.1)

У каждой ловушки есть **уровень**. Шанс успешного прохождения зависит от разницы между уровнем ловушки и уровнем персонажа. В будущем планируется бонус к шансу успеха у опредёлённых персонажей/классов.

Чтобы игрока не наказывала просто случайность, у **каждой** ловушки есть награда за успешное прохождение.

При входе в комнату с ловушкой игроку показывается окно с:

- Описанием ловушки
- Шансом на успех
- Кнопками «Попытаться пройти ловушку» / «Пойти дальше»

Если игрок выбирает «Пойти дальше» — риска и награды нет, комната просто пропускается.

Если игрок выбирает «Попытаться пройти ловушку»:

- **Успех** — персонаж получает награду ловушки.
- **Провал** — персонаж может получить урон
    
    и/или дебафф — зависит от конкретной ловушки (у каждой ловушки свои последствия провала, общего правила нет).
    

### Примеры ловушек для прототипа

**Заминированный сундук** (уровень 3). «При входе в комнату вы замечаете сундук, удобно стоящий прямо посередине комнаты. Что-то подсказывает вам, что это точно ловушка... Но мышеловок без сыра ведь не бывает?»

- Успех: «Внимательно осмотрев сундук, вы замечаете, что он был заминирован. Парой ловких движений вы отключаете ловушку и довольные забираете награду» — обычный сундук с наградой, как за прохождение боевой комнаты.
- Провал: «Стоило вам открыть крышку сундука, как послышался громкий щелчок и комнату озарил взрыв. Что бы ни хранилось в сундуке, это превратилось в шрапнель и полетело в вашу сторону» — ‒15 здоровья, ―20 физ. защиты [правка: HP-урон смягчён с 20 до 15, чтобы оставлять шанс выжить на 1 уровне].

**Сигнализация** (уровень 5). «В комнате царила тишина. Лишь кто-то медленно сопел в углу. Присмотревшись, вы увидели монстров, спящих вокруг сундука. Можно спокойно пройти мимо, а можно попробовать достать сундук...»

- Успех: «Максимально тихо и скрытно вы добрались до сундука и смогли умыкнуть его не разбудив никого» — обычный сундук с наградой, как за прохождение боевой комнаты.
- Провал: «Стоило вам коснуться сундука, как плитка пола под вами предательски скрипела. Все монстры проснулись и они крайне недовольны» — начинается бой со всеми монстрами комнаты, у монстров баф +10% урона.

**Идол** (уровень 7). «В длинной комнате вы замечаете золотого идола, стоящего на пьедестале. Его точно можно успешно продать кому-то, если вынести отсюда. Только, получится ли?»

- Успех: «Быстро заменив идола на камень, вы удаляетесь со своей добычей» — +500 валюты забега (напрямую, без предметов, не через сундук).
- Провал: «Стоило вам поднять идола с пьедестала, как что-то под ним щёлкнуло и с потолка на вас покатился каменный шар. Вы едва успеваете от него убежать, но силы вас покинули» — ‒10% урона и ‒10% скорость атаки в следующем бою.

# 6. Привал

## 6.1 Триггер привала

Привал предлагается после каждой пройденной комнаты (согласно Loop Забега, раздел 1), если у игрока остались рационы.

Каждый привал тратит **1 рацион**. Рационы — единственный гейт механики: 1 рацион = 1 привал. Когда рационы заканчиваются — привалы больше не предлагаются.

## 6.2 Действия на привале

Старые действия из первоначального питча (потренироваться, изучить навык, изготовить расходник) **убраны** — они больше не актуальны, т.к. навыки теперь качаются через левел-ап (см. 3.5), а общая система характеристик для тренировки больше не существует.

Актуальные действия:

- **Отдых.** Происходит автоматически (не требует выбора игрока). Восстанавливает **50% от максимума здоровья** (черновое значение). Это значение может увеличиваться прокачкой зданий в городе, а также дополнительными навыками/предметами.
- **Смена снаряжения.** Доступна не только на привале, а в любой момент забега, за исключением боя и активных текстовых ивентов. Бесплатна, не требует рациона.

## 6.3 Сцена на привале

Если соблюдены определённые условия, на привале может запуститься сцена визуальной новеллы (для прототипа — 3 такие сцены, см. раздел 0).

**Условия запуска сцены** (все три фактора действуют одновременно):

1. **Уровень отношений с персонажем** — параметр мета-прогрессии.
    
    [DRAFT] Копии из гачи повышают максимальный доступный уровень отношений (каждая копия = +1 к потолку, точное число открыто). Забеги дают очки отношения, которые прокачивают уровень в пределах этого потолка: успешное прохождение (победа) = 100 очков, поражение = 50 очков. Порог уровня 1→2 = 100 очков (1 успешный забег), порог 2→3 = 200 очков (ещё 2 успешных забега после достижения 2 уровня). Пороги для уровней выше 3 пока не определены.
    
2. **Этаж подземелья**, на котором происходит привал.
3. **Комната, в которой был начат привал.** Например, комната «Горячие источники» (подтип особой комнаты, см. 5.3) даёт бонус к восстановлению здоровья на привале и запускает тематическую сцену в соответствующем антураже.

**Вариативность по уровню отношений:** для одной и той же комбинации (этаж + комната) могут существовать разные варианты сцены в зависимости от уровня отношений: чем выше уровень отношений — тем «горячее» может быть сцена.

**Возрастной рейтинг: 16+ для прототипа** — без явного контента, только намёки/подтекст. Решение о повышении рейтинга (вплоть до 18+) откладывается до показа прототипа издателям.

### Примеры сцен для прототипа (краткое описание, без полного текста — согласно 10.5 для прототипа достаточно статичного текста/картинки):

**«У костра».** Триггер — случайный привал, 1 раз за забег (не привязан к конкретной комнате/этажу, только от уровня отношений — упрощённый вариант условий из общего правила выше).

- Низкий уровень отношений (ниже 3): Дженифер и игрок сидят у костра, обсуждая, почему она решила стать авантюристом и начала спускаться в подземелья. После разговора Дженифер уходит в свою палатку спать.
- Высокий уровень отношений (3 и выше): тот же костёр, но разговор более личный — прошлое Дженифер, её семья и т.д. Заканчивается тем, что она засыпает на плече у игрока.

**«Горячие источники».** Триггер — привал в комнате «Горячие источники» (см. 5.3), согласно общему правилу триггера выше.

- Низкий уровень отношений: классическая аниме-сценка — Дженифер, прикрываясь полотенцем, выгоняет игрока, случайно увидевшего её в воде.
- Высокий уровень отношения (3 и выше): Дженифер спокойно сидит в воде (всё ещё прикрыта полотенцем), разгаривает с игроком, возможен лёгкий флирт.

[ОТКРЫТЫЙ ВОПРОС: третья сцена из 3 (согласно Scope, раздел 0) пока не описана — выше 2 локации с по 2 варианта каждая (низкий/высокий уровень отношений).]

# 7. UI/UX flow

## 7.1 Внешний хаб (вне подземелья)

- **Главный хаб/деревня.** Центральный экран для навигации между остальными экранами хаба и входом в подземелье (через 7.2).
- **Экран зданий.** Апгрейд Кузницы/Храма/Таверны (см. 8.1) — текущий уровень, следующий бонус, стоимость апгрейда в мета-валюте (стоимость пока открытый вопрос).
- **Экран гачи.** Призыв/открытие персонажей/предметов (для прототипа — 10 предметов-заглушек и 2 персонажа, см. раздел 0). Детали самой гача-механики вынесены в раздел 11.
- **Экран колоды ветеранов.** Отдельный раздел для просмотра завершённых персонажей (статы, снаряжение, уровень силы) вне контекста экрана результатов забега. Используется также при выборе наставника (см. 1, п.3).
- **Экран персонажей.** Список доступных игроку персонажей (полученных в гаче), их био, открытые ВН-сцены (связано с уровнем отношений, см. 6.3).

## 7.2 Флоу забега (в подземелье)

Последовательно, согласно Core Loop (раздел 1):

1. **Экран выбора подземелья.** Список доступных подземелий (в прототипе — 1 шт.).
2. **Экран выбора персонажа.** Список подходящих персонажей (в прототипе — 1 шт.).
3. **Экран выбора наставника.** В прототипе — автоматический/заглушка (см. 1, п.3), может быть простым попапом без реального выбора.
4. **Попап запуска.** Оповещение о модификаторах подземелья перед стартом (см. 1, п.4).
5. **Экран забега.** Основной экран, активен пока игрок внутри подземелья. Сверху — **полоска прогресса этажа** (без полноценной карты — для прототипа достаточно приблизительного отображения пройденных/оставшихся комнат, с приблизительным общим их количеством на этаже, см. 2.1/8.4). Переходы между комнатами — последовательные, без отдельного экрана карты. Внутри экрана забега последовательно сменяются контент в зависимости от типа комнаты:
    - **Бой** (см. раздел 4) — реал-тайм, HP-бары персонажа/противников, таргетинг кликом, переключатель авто/ручного режима активного навыка, кнопка активного навыка (активна по готовности кулдауна).
    - **Событие/текстовый квест** (см. 5.4) — попап с описанием ситуации и вариантами выбора.
    - **Ловушка** (см. 5.5) — попап с описанием, шансом успеха, кнопками «Попытаться»/«Пойти дальше».
    - **Торговец** (см. 5.2) — список предметов, покупка за валюту забега.
    - **Сундук/лут-анимация** (см. 8.2) — появляется после любой пройденной комнаты, анимированное вскрытие с лутом и валютой забега.
    - **Окно выбора навыка (левел-ап)** (см. 3.5) — 3 карточки навыков на выбор.
    - **Привал** (см. раздел 6) — автоматический отдых, минимальный UI (возможно просто uведомление/анимация восстановления здоровья), кнопка смены снаряжения доступна здесь же.
    - **Сцена ВН** (условная, см. 6.3) — полноэкранный режим ВН.
6. **Экран результатов забега.** Победа/поражение, список наград (см. 1, п.7). После этого персонаж добавляется в колоду ветеранов (см. 1, п.8) — возврат в главный хаб.

[ОТКРЫТЫЙ ВОПРОС: детальный мокап экрана (какие кнопки/поля отображаются и когда они активны/неактивны) для каждого экрана пока не детализирован — может потребоваться при вёрстке UI, но для Claude Code этого уровня достаточно для старта прототипа.]

# 8. Экономика прогрессии и баланс

## 8.1 Мета-прогрессия: здания деревни

Согласно Scope (раздел 0) — 3 здания по 5 уровней каждое, с уникальным бонусом на 5 уровне.

**Кузница.** Повышает уровень стартового снаряжения персонажа. Даёт бонус к броне персонажа. На максимальном уровне (предварительно, для прототипа) даёт возможность восстанавливать часть физической защиты (брони) на привале (см. 3.3).

**Храм.** Увеличивает магический щит (см. 3.3). Снижает уровень дебаффов в подземелье. На максимальном уровне (для прототипа) даёт возможность 1 раз перезапустить забег в подземелье в случае поражения.

**Таверна.** Даёт больше рационов на забег. Увеличивает восстановление здоровья после привала (см. 6.2, базовые 50%). На максимальном уровне (для прототипа) даёт случайные бонусы после привала.

**Кузница** — бонусы по уровням:

1. +1 уровень стартового снаряжения персонажа
2. +10 физической защиты (брони)
3. +2 уровня стартового снаряжения (складывается с 1 уровнем — итого +3 уровня суммарно)
4. +20 физической защиты (брони)
5. Восстанавливает 50% брони на привале (складывается с другими источниками восстановления брони, например с пассивным навыком стартового персонажа)

**Храм** — бонусы по уровням:

1. +10 магический щит
2. Снижает или убирает дебафф 2го этажа подземелья (в прототипе)
3. +20 магический щит
4. Снижает или убирает дебафф 3го этажа подземелья (в прототипе)
5. 1 попытка перезапуска забега в случае смерти

**Таверна** — бонусы по уровням:

1. +5 рационов на забег
2. +10% восстановления здоровья на привале
3. Ещё +5 рационов на забег (итого +10 суммарно с 1 уровнем)
4. +20% восстановления здоровья на привале (складывается с 1 уровнем — итого +30% суммарно)
5. Даёт случайные бонусы для персонажа после привала (бонус действует 3 комнаты)

**Стоимость апгрейда по уровням** [DRAFT, одинаковая шкала для всех 3 зданий, в мета-валюте]:

- Уровень 1: 100
- Уровень 2: 200
- Уровень 3: 400
- Уровень 4: 800
- Уровень 5: 1500

## 8.2 Награды за бой в комнате

Награда за победу в боевой комнате зависит от:

- Этажа/уровня комнаты
- Потенциальных навыков на улучшение наград (у персонажа могут быть навыки/пассивки, увеличивающие количество/качество лута)

Не зависит от конкретного побеждённого монстра — у монстров нет индивидуальных лут-таблиц.

**Механика выдачи:** после прохождения комнаты в ней появляется **сундук**, из которого с красивой и залипательной анимацией спавнится случайный лут (по аналогии с открытием сундуков в Vampire Survivors / открытием кейсов в CS2). Цель — сделать каждый забег максимально затягивающим для игрока.

Тех. реализация анимации сундука — ОБНОВЛЕНО [DRAFT]: через tween-библиотеку (например DOTween), без покадровой/рисованной анимации. Разбивка на 5 последовательных шагов (каждый — отдельный tween, тайминги/цвета настраиваются отдельно после, это не блокирует старт разработки):

1. Формирование ленты из ~20 слотов-иконок, заполненных случайными предметами по таблице редкости ниже (визуальный «шум»). Реальная награда вставляется в фиксированную позицию ленты (слот 17 из 20).
2. Прокрутка: лента движется с ease-out за 3-5 секунд, останавливаясь так, чтобы иконка награды совпала с индикатором по центру.
3. Кнопка «Пропустить» доступна с начала прокрутки — мгновенно завершает tween, лента сразу показывает результат.
4. Приземление: вспышка/подсветка на приземлившемся слоте + Particle System burst + текстовый reveal названия/редкости.
5. Счётчик валюты: число валюты забега накручивается от 0 до финального значения.

Из сундука игрок **всегда** получает и предметы (лут), и **валюту забега** одновременно — валюту можно потратить у торговца (см. 5.2).

Опыт для левел-апа выдаётся автоматически (отдельно от сундука), согласно Loop Забега (раздел 1).

**Валюта забега из сундука** [DRAFT]: базовая сумма = 10 × номер этажа, ±20% случайного разброса. Сундук босса — x5 к базовой сумме.

**Редкость предмета в сундуке** [DRAFT, 3-тирная шкала, согласно понятию «тира» из 3.2]: Обычный 60% / Редкий 30% / Эпический 10%. Сундук босса гарантированно даёт минимум Редкий предмет.

## 8.3 Формула шанса успеха (ловушка/квест)

Применяется к механикам из 5.4 (текстовый квест) и 5.5 (ловушка).

Формула — **линейная** [DRAFT, требует баланс-тестов]:

`ШансУспеха = 50% + (УровеньПерсонажа − УровеньЛовушки/Квеста) × 10%`

Значение ограничивается в диапазоне **5%–95%** (чтобы исход никогда не был 100% гарантирован или 0% гарантированно провальный).

При равных уровнях персонажа и ловушки/квеста — базовый шанс 50/50. Бонусы от класса/навыков (см. 5.4, 5.5) прибавляются к итоговому значению до клампа.

## 8.4 Механика выбора типа комнаты: «Мешок» (bag randomization)

Вместо простых весов/процентов используется **механика мешка/стопки** (подобно Tetris 7-bag или лут-системам в играх Blizzard): все возможные типы комнат складываются в общий пул («мешок»). Когда комната определённого типа выпадает игроку, она удаляется из пула до тех пор, пока мешок не опустеет. Это предотвращает ситуации вроде нескольких комнат торговца подряд в одном забеге.

**Мешок пересоздаётся заново на каждом этаже** — каждый этаж начинается с новым полным мешком.

**Состав мешка** [DRAFT, предварительно для одного этажа; может масштабироваться на более глубоких этажах, см. 2.1]:

- Боевых комнат — 7
- Комнат торговца — 1
- Ловушек — 3
- Особых комнат — 1 (предварительно — комната с триггером ВН-сцены и бонусом к лечению, см. 6.3)

**Итого:** 12 комнат в мешке на этаж (босс не входит в мешок — он фиксирован, см. 2.2). Это также задаёт количество обычных комнат на этаже (см. 2.1) — для первого этажа это 12; точный рост мешка на более глубоких этажах пока не определён.

## 8.5 Мета-валюта и гача-валюта (награда за забег)

Обе валюты начисляются за завершённый забег (победа или поражение), НЕ связаны с валютой забега (которая тратится только у торговца и обнуляется, см. 5.2/8.2).

[DRAFT] **Мета-валюта** (на апгрейд зданий, см. 8.1): победа = 80, поражение = 30.

[DRAFT] **Гача-валюта** (отдельная от мета-валюты, только на призывы гачи): 15 за любой завершённый забег (победа или поражение — одинаково). Стоимость 1 призыва: 50 гача-валюты.

**Баланс-расчёт на 5 забегов** [DRAFT, требует плейтестов]:

- За 5 забегов (даже при всех поражениях) игрок накопит минимум 150 мета-валюты — хватает на 1 уровень Кузницы (100, см. 8.1), что даёт +1 уровень стартового снаряжения — ключевой шаг для пробивания брони Скелета/босса (см. 2.2).
- За 5 забегов игрок накопит минимум 75 гача-валюты — хватает на 1 призыв (50), т.е. минимум 1 копия персонажа гарантирована до конца 5го забега, даже без учёта валюты из сундуков.
- Вывод: без апгрейда Кузницы и/или копии персонажа (повышающей уровень стартового снаряжения через гачу, см. 3.5) — игрок не может пробить броню Скелета/босса стартовым оружием — это и есть требуемый гейт против прохождения с первой попытки.

## 8.6 Балансный аудит и потолки

[DRAFT] При проверке комбинаций из 3.9/3.10 найдены два места, требующие жёсткого клампинга:

**Шанс крита** — при стеке источников (навык «Критические атаки» + бонус Стального гладиуса + кольца/амулеты удачи) суммарный шанс крита легко превышает 90%, что в связке с Вампиризмом Кровавого меча даёт почти постоянный самолеч и тривиализирует угрозу (ловушки/босса). **Потолок: суммарный шанс крита клампится на 75%.**

**Восстановление брони на привале** — при стеке «Полевого ремонта» (до 50%) + Кузницы ур.5 (50%) + пассивки Молота кузнеца сумма легко превышает 100%. Не ломает баланс (просто даёт полное восстановление), но требует клампинга в коде во избежание багов. **Потолок: суммарное восстановление брони клампится на 100%.**

Остальные комбинации (Заморозка+Пробивание+Разрушение брони против брони врагов; Амбидекстрия + 2 топора) — сильные, но требуют серьёзных инвестиций и являются интендированным путём прохождения гейта из 2.2, а не эксплойтом.

# 9. Данные и сохранение

## 9.1 Сохранение забега посередине

Для прототипа **не реализуется**. Забег не сохраняется посередине прохождения — при закрытии игры текущий забег теряется полностью. Сохраняется только состояние **между забегами** (см. 9.2). Это решение принято сознательно, чтобы не тратить ресурсы разработки на mid-run save и связанные с ним баги.

## 9.2 Что сохраняется между сессиями

- **Колода ветеранов** — список завершённых персонажей с их финальными статами/навыками/снаряжением (см. 1, п.8).
- **Мета-валюта** — общий баланс.
- **Уровни зданий деревни** — Кузница/Храм/Таверна, каждое 0-5 (см. 8.1).
- **Гача-данные** — полученные персонажи (с количеством копий каждого) и полученные предметы.
- **Количество прохождений подземелья по каждому персонажу** — вместе с количеством копий из гачи определяет уровень отношений (см. 6.3).
- **Открытые ВН-сцены** — список уже увиденных сцен по каждому персонажу (для экрана био/галереи персонажа, см. 7.1).

## 9.3 Формат хранения

[DRAFT, техническое решение для прототипа]: сериализация в JSON, сохранение в локальный файл (Application.persistentDataPath в Unity). Облачные/сетевые сохранения — вне скоупа прототипа.

## 9.4 Черновые классы данных

# 10. Технические заметки для Unity

## 10.1 Общий подход

- **Платформа:** PC (standalone).
- **Рендер:** 2D, UI-driven (Canvas-based) — без 3D-сцен для прототипа.
- **Архитектура:** data-driven. Большинство контента (навыки, предметы, события/ловушки/квесты, противники, модификаторы, здания) — как ScriptableObject-ассеты, а не хардкод в коде. Это соответствует духу ГДД (много таблично описанных сущностей) и облегчает добавление контента без правки кода.

## 10.2 Рекомендуемая архитектура состояний

Для прототипа — enum + switch, без полноценного State Pattern (быстрее собрать, легче дебажить):

```
RunState: CharacterSelect, MentorSelect, RunSetup, InFloor, RunComplete, RunFailed

FloorState/RoomState: FloorStart, RoomEntry,
  CombatResolve | EventResolve | TrapResolve | MerchantResolve | VNTriggerResolve,
  RewardChest, LevelUpChoice (если получен уровень),
  CampPhase, PathContinue, FloorEnd
```

Соответствие с Loop Забега (раздел 1) и Флоу забега (раздел 7.2) прямое.

Важно: бой в реальном времени (см. раздел 4) требует не событийной/пошаговой логики, а таймер-базированного тика: у каждого участника боя (персонаж/противник) свой таймер атаки, обновляемый в Update()/через корутины, срабатывающий по достижении интервала = 1 / СкоростьАтаки (см. 3.2).

## 10.3 Рекомендуемые менеджеры

- **GameManager** — общий вход, хранит SaveData (раздел 9), переходы между хабом и забегом.
- **HubManager** — навигация между экранами хаба (раздел 7.1): деревня, здания, гача, ветераны, персонажи.
- **DungeonManager** — управляет RunState, оркестрирует генерацию подземелья (раздел 2).
- **FloorManager** — управляет FloorState/RoomState внутри этажа, включая логику мешка с комнатами (8.4).
- **CombatManager** — логика реал-тайм автобоя: таймеры атаки, таргетинг, активация навыков (раздел 4).
- **RewardManager** — расчёт наград, логика сундука, выдача опыта/валюты забега/лута (8.2).
- **LevelUpManager** — логика окна выбора навыка при левел-апе (3.5).
- **CampManager** — авто-отдых, проверка условий запуска ВН-сцены (раздел 6).
- **CharacterManager** — текущие HP/навыки/уровень персонажа в забеге.
- **EquipmentManager** — 8 слотов снаряжения, агрегация статов (урон/физ.защита/маг.щит, см. 3.2-3.4).
- **SaveManager** — сериализация/десериализация SaveData (раздел 9).
- **VNManager** — воспроизведение сцен визуальной новеллы и текстовых квестов (5.4). Подробности формата контента — см. 10.4.

## 10.4 Формат контента для ВН-сцен и квестов (без редактирования в Unity)

[DRAFT] Цель: чтобы новую сцену/квест можно было добавить, создав текстовый файл вне Unity, без открытия редактора.

Сцены/квесты хранятся как отдельные JSON-файлы в папке вне Unity-проекта (например StreamingAssets/Content/Scenes и StreamingAssets/Content/Quests). VNManager читает их напрямую в игре — новая/изменённая сцена подхватывается без пересборки проекта.

Общая структура файла (обслуживает и сцены на привале, и квесты из 5.4):

```json
{
  "id": "campfire_low",
  "characterId": "jennifer",
  "lines": [
    { "speaker": "Дженифер", "emotion": "neutral", "text": "..." },
    { "speaker": "Игрок", "emotion": null, "text": "..." }
  ],
  "choices": [
    { "text": "...", "successChance": null, "onSuccess": {...}, "onFail": {...} }
  ]
}
```

Ключевые моменты: **каждая реплика помечена именем говорящего** (поле `speaker`) — не сплошной текст; поле **`emotion`** заложено заранее (для прототипа всегда один спрайт/портрет на персонажа, но структура данных уже готова к переключению между несколькими спрайтами-эмоциями в будущем); опциональный блок **`choices`** используется только для квестов (5.4) — у простых Н-сцен на привале его нет, только последовательные `lines`.

Маппинг `emotion` → конкретный спрайт хранится отдельно в Unity (пер персонаж, словарь emotion→Sprite) — это единственная часть, требующая работы в Unity (добавить спрайт и привязать к ключу), сам текст сцен — нет.

## 10.5 Вне скоупа прототипа (явно НЕ реализуем сейчас)

- Финальный арт, звук, анимации (плейсхолдер-спрайты/примитивы допустимы)
- Полноценная гача-монетизация (платежи, баннеры, pity-система)
- PvP-арена, бесконечный данж, ивентовые данжи, клановые данжи (см. раздел 11)
- Полноценная ВН-система для истории персонажей — для прототипа сцены на привале можно показывать статичным текстом/картинкой без полноценной диалоговой системы
- Mid-run сохранение забега (см. 9.1)
